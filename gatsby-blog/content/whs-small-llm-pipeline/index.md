WhiteHat School 4기 팀 프로젝트에서 소형 open-weight 모델을 여러 역할로 연결하는 취약점 분석 파이프라인을 개발했다. 나는 소형 모델과 Teacher 모델 후보를 조사하고, SFT와 후보 모델 비교 실험에 참여했다.

## 한 번의 응답을 검증 가능한 단계로 나누기

공개 저장소의 파이프라인은 C/C++ 메모리 버그의 후보 지점 탐색, 코드 분석, 후보 판정, PoC 구성과 실행 검증을 역할별로 나눈다. 모델이 의심스럽다고 답한 것과 실제 실행에서 문제가 재현된 것은 다르다. 실행 단계의 결과를 분리하면 분석이 틀렸는지, 재현 조건이 부족했는지 구체적으로 돌아볼 수 있다.

포트폴리오에 정리한 실험에서는 소형 모델과 자체 GPU 서버, vLLM을 사용했다. 모델 비교에서 출력이 그럴듯한지만 보면 단계별 실패를 놓칠 수 있다. 같은 과제를 놓고 후보 판단과 실행 검증을 따로 기록하는 것이 중요했다.

## 중간 결과를 해석하는 방법

포트폴리오 작성 시점에 기록한 CyberGym 결과는 평가 항목 8개 중 5개 성공이다. 같은 시점에 취약점 4건을 제보했다고 기록했다. 5/8은 해당 평가 범위의 결과이고, 제보 수는 제보한 보고서 수다. 평가 조건과 처리 상태가 달라지면 비교에 필요한 근거도 달라진다.

다음 실험에서는 슬라이서와 프롬프트를 한 번에 바꾸기보다 한 항목씩 바꾸고 싶다. 같은 입력을 사용해 단계별 성공 여부, 걸린 시간, 실패 이유를 남기면 개선 효과를 구분하기 쉬워진다.
